# Open Reel

Open Reel is a minimal Electron desktop media library with background catalog search, torrent queue management, and local video playback.

## Features
- Search the AnimeTosho JSON feed from inside the app (no browser window is opened).
- Filter search results by resolution and sort by date, size, or title.
- Add a result to the queue via its magnet link or `.torrent` URL.
- Paste magnet links or direct `.torrent` URLs manually.
- Pause/resume downloads, view progress/speed/peers, open the download folder, and play completed video files.
- Open local video files in the built-in player.
- Hardened renderer: context isolation, no Node integration, IPC through a preload bridge.

## Requirements
- Node.js 20+ and npm
- Windows, macOS, or Linux

## Run from source
```bash
npm install
npm start
```

## Build an installer
```bash
npm run dist
```
The output is written to `dist/`.

## Catalog note
The app queries `https://feed.animetosho.org/json?qx=1&q=...&page=1`. The legacy AnimeTosho feed/service may be unavailable or incomplete; this app displays an in-app error instead of opening a browser. The `animetosho.net` domain may not provide the same API. Verify the source's current availability and terms before relying on it.

## Downloads and legal use
Torrent search results can include material whose copyright status varies. Only download or share material you are legally authorized to access. You are responsible for complying with local law and the source's terms.

## Known limitations
- No packaged installer is included; build it on your platform using `npm run dist`.
- This first version does not persist torrent queue metadata after app restart.
- Some codec/container combinations may not play in Electron's built-in HTML5 video player.
- `.torrent` URLs are accepted if they are direct URLs ending in `.torrent`; links requiring a website session will not work.


## Troubleshooting: ERR_REQUIRE_ASYNC_MODULE
The main process dynamically imports WebTorrent 2.x because it is an ES module. If you extracted an older ZIP, replace its `main.js` with the updated one from this archive, then run `npm install` again.


## Download engine compatibility fix (v0.6)
This build pins WebTorrent to the stable 1.9.7 CommonJS API and parse-torrent 9.1.5 to avoid the WebTorrent 2.x torrent-ID parsing error reported in some environments. Install dependencies from scratch with `npm install` in this extracted folder. This has not been tested against the user's specific catalog entry; test only with torrents you are authorized to download.

## v0.8 thumbnails and in-app playback
Library thumbnails are generated by ffmpeg-static and cached under the app's user-data folder. Non-browser-friendly formats such as MKV are converted to H.264/AAC MP4 in a cache and played in the built-in player. The first playback can take time and requires extra disk space; subsequent playback reuses the converted file. This has not been tested on the user's Windows system.


## Startup performance fix (v0.9)
The main window is now created before loading WebTorrent, and the torrent engine initializes asynchronously. Library thumbnails are generated only as cards approach the visible viewport, avoiding duplicate ffmpeg jobs and large bursts of CPU/disk activity. This change has syntax-level checks only; please test on the target Windows machine.


## Clean display names (v0.11)
The library now derives display-only titles from file/folder names: converts dots/underscores to spaces, normalizes S01/S01E01 markers, removes common release metadata after resolution/source/codec markers, removes release-group suffixes, and keeps useful language tags such as German. Original files and folder names are not renamed.


## Title display follow-up (v0.12)
Fixes the video-card title binding so the cleaned display title is used for individual video files as well as folders. The breadcrumb also displays cleaned folder names. Original paths and filenames remain unchanged.


## Windows playback only (v0.13)
Removed the embedded video player and bottom playback bar. Selecting a library video, choosing a local file, or opening a completed download now calls Windows `shell.openPath`, which launches the default app associated with that video format. Open Reel does not convert or play videos internally; FFmpeg remains only for thumbnail generation.


## AniBrary (v0.14)
Renamed the app to AniBrary, minimized explanatory UI copy, and moves season/episode markers to the beginning of displayed titles (for example `S01 EP01 · Series Name German`). Original filenames and folders are unchanged.


## AniBrary v0.15
Adds AniBrary app branding and a custom A icon for the app window/build. Download controls include pause/resume, remove from queue while keeping downloaded files, and a separate explicit delete-files action. Each action catches errors and reports the result.


## Download action reliability (v0.16)
Download action handlers now prevent double-clicks, display progress/error feedback, and surface uncaught UI errors. Pause/resume validate engine state; removal handles callback/promise variations and confirms the torrent leaves the active client before updating the queue.


## Active-download controls (v0.17)
Updates queue snapshots every second and exposes pause/resume actions while downloads are active. Pause closes active peer connections while retaining the torrent and its storage; resume reannounces discovery so peers can be found again. This has syntax-level validation but requires real Windows/WebTorrent testing.
